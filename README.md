# ОСББ — облік нарахувань та оплат

Курсова робота: вебзастосунок для обліку послуг ОСББ, нарахувань і платежів мешканців.

Технології: C#, ASP.NET Core MVC (.NET 10), Entity Framework Core, SQL Server, Bootstrap.

Є довідники, особові рахунки, історія тарифів, лічильники, щомісячні показання, нарахування, оплати та поточні баланси. Доступ розмежовано за ролями.

## Запуск

Потрібні .NET SDK 10 і SQL Server. Команди виконуються з кореня репозиторію.

1. У SSMS виконайте `database/01_CreateDatabase.sql`. Він створить базу `OSBB_Billing`. Якщо вона вже створена, цей крок пропустіть.
2. За потреби додайте тестові дані скриптом `database/02_DemoData.sql` у порожню базу.
3. Налаштуйте локальне підключення та запустіть застосунок:

```powershell
dotnet restore --locked-mode
dotnet user-secrets set "ConnectionStrings:OsbbBilling" "Server=localhost;Database=OSBB_Billing;Integrated Security=True;Encrypt=True;TrustServerCertificate=True" --project src/OsbbBilling.Web
dotnet run --project src/OsbbBilling.Web --launch-profile http
```

Приклад підключення розрахований на локальний SQL Server із Windows Authentication. Налаштування зберігається поза репозиторієм у User Secrets. `TrustServerCertificate=True` використовується для локального сервера.

Відкрийте адресу з консолі та увійдіть у систему. Перевірка БД доступна бухгалтеру в Development.

## Доступ

Для даних із `02_DemoData.sql` є тестові логіни `accountant`, `chair`, `owner1` та `owner2`. Навчальний пароль для них — `OsbbDemo2026!`. Це вигадані облікові записи для локальної демонстрації.

- Бухгалтер веде довідники, відкриває рахунки, змінює відповідального платника, виконує нарахування та реєструє оплати.
- Голова ОСББ переглядає довідники, особові рахунки, нарахування та оплати.
- Власник бачить особові рахунки, прив’язані до його облікового запису.

Паролі перевіряються за хешами в `Users`. Роль і платник беруться з БД. Неактивний обліковий запис не може увійти; блокування або зміна ролі скасовують попередню сесію під час наступного запиту. Після п’яти спроб входу за хвилину з однієї IP-адреси сервер повертає 429.

Рахунки діють за повними місяцями. Дата завершення не входить у період. Під час зміни платника попередній рахунок завершується, а новий відкривається з тієї самої дати в одній транзакції. Нарахування, оплати, борг та аванс зберігаються на попередньому рахунку.

Тарифи й підключення послуг діють за повними місяцями. Нова версія тарифу зберігає попередню ціну. Завершення послуги не може виключати наявні нарахування або залишати діючий лічильник поза періодом підключення.

Показання вносяться послідовно за місяцями та не можуть зменшуватися. До проведення нарахувань можна виправити дату й значення показання. Показання, використане в розрахунку свого або наступного місяця, захищене від змін.

Бухгалтер виконує нарахування за обраний місяць у розділі «Нарахування». Розрахунок охоплює всі активні послуги та застосовує наявний аванс. Повторний запуск не створює дублікатів. За відсутності рахунку, тарифу чи потрібних показань операція скасовується повністю.

Оплата реєструється за унікальним номером платіжного документа. Сума спочатку погашає найстаріші нарахування цього рахунку, а залишок стає авансом. У деталях оплати видно її розподіл. Завершений рахунок можна оплатити для погашення старого боргу. Зареєстровані оплати не редагуються та не видаляються.

Розділ «Баланси» показує поточні підсумки кожного рахунку за весь період обліку. Борг визначається за непогашеними нарахуваннями, аванс — за нерозподіленими оплатами. Сальдо дорівнює різниці нарахувань і оплат. У картці рахунку доступні ці підсумки, а в деталях нарахування — зараховані платежі та залишок боргу. Історичний баланс на довільну дату не розраховується.

## Файли проєкту

- `src/OsbbBilling.Web` — MVC-застосунок.
- `database` — структура БД, тестові дані, приклади операцій і перевірки.
- `tests/OsbbBilling.Tests` — перевірки моделі, форм, прав доступу та операцій із рахунками.

`03_Demonstration.sql` виконує операції з даними, а `04_Verification.sql` перевіряє правила БД. Використовуйте їх у тестовій базі. Застосунок самостійно не створює та не змінює схему БД.

## Перевірки

Без SQL Server:

```powershell
dotnet test --filter "Category!=Integration"
```

Для перевірки відповідності моделі наявній БД та читання всіх таблиць задайте локальну змінну `OSBB_TEST_CONNECTION_STRING` і виконайте `dotnet test --filter "FullyQualifiedName~DatabaseReadTests"`. Ці тести виконують лише запити читання.

Для SQL-тестів запису задайте `OSBB_SQLSERVER_TEST_CONNECTION_STRING` із доступом до створення тестових БД та виконайте `dotnet test --filter "Database=SqlWrite"`. Кожен тест створює окрему базу з префіксом `OSBB_Billing_IntegrationTest_` і видаляє її після перевірки. Перевіряються відкат при помилці, одночасні зміни, тарифні періоди та збереження фінансової історії.
